# 06 帧模型

## 1. 范围

定义受控即时模式的全部运行规则：控件 ID、状态存储、节点树、帧的阶段与调度、三级脏标记、损伤矩形、动画与定时器，以及应用构建函数必须遵守的契约。依据 ADR 0005、ADR 0006。

事件如何路由到控件见 08；测量与排布算法见 07；绘制接口见 04。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 界面上下文 (`Ui`) | 一个应用窗口的全部帧模型状态：状态存储、两棵节点树、脏标记、动画表。每个应用窗口一个。 |
| 主根 / 弹出根 | 主根对应应用窗口客户区；每个打开的弹出层有一个弹出根，对应其弹出窗口。弹出根在宿主的构建函数中声明。 |
| 构建遍 (build pass) | 构建函数的一次完整执行。一帧内至多两遍。 |
| 布局输入 | 决定一个节点测量结果的全部数据：布局参数、子节点列表、内容度量键。 |
| 绘制键 (paint key) | 控件为节点提供的 64 位值，概括其全部影响外观的属性。 |
| 布局反馈 | 节点声明"我的构建结果依赖我自己的最终矩形"，矩形变化时需要重新构建。 |
| 帧后动作 | 在构建中登记、于本帧提交之后执行的闭包。用于会重入消息循环的操作。 |
| 失效风暴 | 没有外部失效源的情况下，帧连续自我触发。属于编程错误。 |

## 3. 规范条款

### 3.1 控件 ID

**REQ-FRAME-001**　每个节点**必须**有一个 `WidgetId`，由三部分经固定种子的 64 位哈希得出：父种子（ID 栈顶）、调用点（`@src()` 的文件、行、列，编译期求值）、可选的显式键。

**REQ-FRAME-002**　所有会产生节点的控件 API 在 `ui: *Ui` 之后的首个参数**必须**是 `src: std.builtin.SourceLocation`，由调用方传入 `@src()`。显式键通过各控件选项结构中统一命名的 `key` 字段提供，类型为 `ui.Key`（可由整数或字节串构造）。

**REQ-FRAME-003**　容器类节点在其 `begin`/`end` 之间**必须**自动把自身 ID 压入 ID 栈作为子节点的父种子。应用**可以**用 `ui.pushId(key)` / `ui.popId()` 手动增加一层种子而不产生节点。

**REQ-FRAME-004**　同一调用点在一个构建遍内被执行多次（循环、递归、被多次调用的辅助函数）时，调用方**必须**通过显式键或 `pushId` 使每次的 ID 不同。键**应当**取自数据的稳定标识（记录主键、路径），而非会随增删重排而变化的下标；仅当列表不会重排且项无跨帧状态时**可以**用下标。

**REQ-FRAME-005**　一个构建遍内出现两个相同 ID 是编程错误。调试构建**必须**中止并同时报告两处调用点；发布构建**必须**让后出现者复用前者的状态槽、记录一条 `err` 日志（同一 ID 每次运行只记一次）并继续。

**REQ-FRAME-006**　`WidgetId` 的值只保证在一次进程运行内稳定。应用与框架**不得**把它写入磁盘或跨进程传递。需要持久化的界面状态（分隔条位置、列宽）以应用提供的字符串名为键（见 11）。

**REQ-FRAME-007**　`WidgetId.none`（0）保留，表示"无控件"。哈希结果恰为 0 时**必须**改映射为 1。

### 3.2 状态存储

**REQ-FRAME-008**　每个 `Ui` 拥有一个状态存储：以 `(WidgetId, 类型标识)` 为键的状态槽集合。`ui.state(T, id, init)` 在槽不存在时以 `init` 创建，返回的指针在本构建遍结束前有效；跨构建遍**不得**保存该指针。

**REQ-FRAME-009**　同一 ID 以不同类型 `T` 请求状态，得到的是不同的槽。一个节点可以有多个槽。

**REQ-FRAME-010**　状态槽分两种保留级别，由创建时指定：

| 级别 | 回收时机 | 适用 |
|---|---|---|
| `transient`（默认） | 一次构建（含其全部构建遍）结束时，若该次构建未触达此槽，立即回收 | 悬停/按下动画、下拉展开态、临时编辑缓冲 |
| `sticky` | 未被触达时不立即回收，进入每个 `Ui` 的最近最少使用队列，队列超过上限（默认 4096 槽，可配置）时回收最久未触达者；窗口关闭时全部回收 | 滚动位置、树的展开集合、标签页内各页的状态、文本框的撤销栈 |

"触达"指本次构建中对该槽调用过 `ui.state` 或 `ui.retained`。

**REQ-FRAME-011**　保留节点通过 `ui.retained(T, id, level)` 取得。`T` **必须**提供 `init(allocator) T` 与 `deinit(*T) void`。槽回收时框架**必须**调用 `deinit`。保留节点的内存取自状态存储池（02）。 保留级别另有 `pinned`：永不因未触达或 LRU 而回收，只在 `ui.forget`/`forgetSubtree` 或窗口关闭时回收。仅用于持有不可重建的用户数据的保留节点（多行文本编辑区的文档），调用方对其生命周期负责。

**REQ-FRAME-012**　应用**可以**调用 `ui.forget(id)` 立即回收某 ID 的全部槽，或 `ui.forgetSubtree(id)` 回收其在当前树中的全部后代的槽。用于"重置此表单"之类的显式需求。

**REQ-FRAME-013**　框架内建的每节点交互状态（是否悬停、按下、聚焦及其动画进度）与状态槽分开存放，由框架按同样的 `transient` 规则管理，控件无需为其申请槽。凡经 `ui.interact` 登记了指针兴趣的节点，其悬停、按下、焦点环三项过渡由框架按 09 的时长令牌自动推进（`paint` 级），绘制函数经 `PaintCtx.visual` 读取；控件自有的动画（勾选标记、滑块位置等）用 `ui.animate` 的槽位另行登记。

### 3.3 节点树

**REQ-FRAME-014**　构建遍产出节点树：每个节点记录 ID、父子兄弟链接、布局参数（07）、标志位、绘制函数指针、指向属性数据的指针、绘制键。节点与属性数据分配在树竞技场。属性中**可以**保存 `*const text.Layout`，其有效期由 REQ-TEXT-014 保证覆盖保留树的整个存活期；排版缓存的构建代由 `Ui` 在每次构建开始时推进，应用无需关心。

**REQ-FRAME-015**　节点树从一次构建完成起保持有效并不可变，直到下一次构建完成将其替换。纯布局帧、纯绘制帧、帧间的命中测试都使用这棵保留树。

**REQ-FRAME-016**　一个 `Ui` 的节点树有一个主根与零或多个弹出根。弹出根的内容在宿主构建函数内以 `beginPopup`/`endPopup` 声明，其节点属于同一构建遍、共享同一状态存储与 ID 空间，但独立布局、独立绘制到各自的平台窗口。

**REQ-FRAME-017**　每个根有两个绘制层：**内容层**与**覆盖层**。覆盖层在内容层之后绘制，不参与布局、不参与命中测试，仅供拖拽指示、分隔条虚影、调试叠加使用。除此之外不存在 z 序概念：同一层内的绘制顺序即节点的先序遍历顺序。

**REQ-FRAME-018**　节点的绘制函数签名固定为 `fn (ctx: *PaintCtx, node: *const Node) void`。它**必须**是纯函数：输出只取决于节点属性、节点最终矩形、该节点的交互状态与状态槽、主题、当前帧时间戳。它**不得**修改任何状态、**不得**发出失效。同一棵保留树上，框架可以在任意帧对任意节点重复调用它。

**REQ-FRAME-019**　控件**必须**为每个节点提供绘制键。约定：两次构建中同一 ID 的节点若绘制键相同、最终矩形相同、交互状态未变、无活动动画，则框架认定其外观未变，不为其产生损伤。绘制键漏算了某个影响外观的属性属于控件缺陷。

### 3.4 帧的阶段

**REQ-FRAME-020**　一帧由下列阶段按固定顺序组成。标 ◇ 的阶段在不需要时跳过。

| 序 | 阶段 | 工作 |
|---|---|---|
| 1 | 收集 | 取出本轮已到达的全部输入事件、到期定时器、回投闭包（先执行闭包）；采样本帧时间戳 |
| 2 | 分发 | 用**保留树**的几何为事件确定目标，更新悬停/按下/焦点，处理快捷键，把事件排入各目标 ID 的收件列表（08）；据此置脏 |
| 3 ◇ | 构建 | 仅当构建脏。互换树竞技场，执行构建函数（至多两遍，见 3.6），回收未触达的 `transient` 槽 |
| 4 ◇ | 布局 | 仅当构建过或布局脏。测量与排布（07）；与旧树比对，复用未变子树的度量；检查布局反馈 |
| 5 | 损伤计算 | 汇总本帧损伤矩形（3.7） |
| 6 ◇ | 绘制 | 仅当损伤非空。按根、按层，对与损伤相交的节点调用绘制函数 |
| 7 ◇ | 提交 | 仅当绘制过。呈现帧缓冲（04） |
| 8 | 收尾 | 执行帧后动作；重置帧竞技场；清空一次性输入结果；决定下次唤醒（3.9） |

**REQ-FRAME-021**　本帧时间戳在收集阶段采样一次。本帧内所有动画求值、定时器判定、光标闪烁相位**必须**使用这同一个时间戳。

**REQ-FRAME-022**　每个根独立执行阶段 4–7；某个根没有损伤时，该根不绘制、不提交。

**REQ-FRAME-023**　帧不可重入。在帧执行期间（包括构建函数内）触发的失效**必须**被记录并导致下一帧，而不是嵌套执行。帧后动作在帧状态完全清除、帧竞技场重置之后才执行；因此帧后动作启动的嵌套模态循环（原生对话框、拖放）期间由平台层驱动的帧（REQ-PLAT-025）是独立的帧，不构成重入。

### 3.5 构建函数契约

**REQ-FRAME-024**　构建函数**必须**幂等：在没有新事件、模型未变的前提下，连续执行两遍产出的节点树（ID、结构、布局参数、绘制键）完全相同。

**REQ-FRAME-025**　构建函数只**可以**在响应激活类结果（`clicked`、`changed`、`committed` 等，见各控件规范）时修改模型。除此之外**不得**有副作用：不得依赖"每帧恰好调用一次"、不得在其中累加计数或推进时间、不得读取帧时间戳以外的时钟。

**REQ-FRAME-026**　构建函数**不得**阻塞：不得做文件或网络 I/O，不得等待锁。耗时工作交给工作线程并回投结果。

**REQ-FRAME-027**　构建函数**不得**直接调用会重入消息循环的平台功能（原生模态对话框、`platform.messageBox`、拖放的 `DoDragDrop`）。这类操作**必须**用 `ui.afterFrame(closure)` 登记为帧后动作。

**REQ-FRAME-028**　`begin*`/`end*` **必须**严格配对。调试构建在构建遍结束时检查栈平衡，不平衡即中止并报告未闭合容器的调用点；发布构建自动补齐闭合并记录 `err` 日志。

**REQ-FRAME-029**　构建函数**可以**通过 `ui.lastRect(id)` 读取某 ID 在保留树中的最终矩形（lpx）。节点首次出现时返回 `null`。依赖该值决定构建内容的节点**必须**设置布局反馈标志（3.6）。

### 3.6 同帧第二构建遍

**REQ-FRAME-030**　下列任一情况发生时，本帧**必须**在第一构建遍结束后立即执行第二构建遍，再进入布局：
- **激活反馈**：第一遍中有控件向应用返回了激活类结果。理由：应用可能据此修改了在它之前已声明的界面所依赖的数据。
- **显式请求**：构建函数调用了 `ui.requestRebuild()`。

**REQ-FRAME-031**　布局阶段结束后，若任一设置了布局反馈标志的节点的最终尺寸不同于其构建时通过 `lastRect` 看到的尺寸（含首次出现），且本帧尚未执行过第二构建遍，则**必须**回到构建阶段执行第二遍，再重新布局。 同样地，位于 Scroll 容器内、设置了布局反馈标志的节点，若其所在 Scroll 的滚动偏移不同于它构建时看到的值（经 `scrollMetrics` 读取），也触发这一遍——虚拟化控件据此在滚动后声明新的可见项。

**REQ-FRAME-032**　一帧内构建遍**不得**超过两遍。第二遍之后仍存在 REQ-FRAME-030 或 REQ-FRAME-031 的条件时，**必须**以当前结果完成本帧，并置构建脏以请求下一帧。

**REQ-FRAME-033**　事件只投递一次：第二构建遍中，各控件的收件列表为空，激活类结果全部为假；持续性状态（悬停、按下、聚焦、拖拽中）保持。

**REQ-FRAME-034**　第一构建遍的节点树在第二遍开始时丢弃（第二遍重置同一份树竞技场），旧树仍是上一帧完成的那棵。

**REQ-FRAME-035**　调试构建**必须**检测失效风暴：连续 8 帧均由帧内自身触发（激活反馈以外的 `requestRebuild`、布局反馈未收敛、绘制函数外的自失效）且期间无任何外部失效源时，记录一条 `warn` 日志并附触发节点的调用点。

### 3.7 脏标记与损伤

**REQ-FRAME-036**　每个 `Ui` 维护三级脏标记：`build` ⊃ `layout` ⊃ `paint`。置高级别隐含其下各级。`paint` 级别附带损伤矩形或节点 ID。

**REQ-FRAME-037**　允许置脏的来源是封闭集合，对应关系**必须**如下表。表外的代码路径不得置脏。

| 失效源 | 置脏级别 |
|---|---|
| 路由到某控件收件列表的输入事件（按键、字符、按下、释放、滚轮、被捕获期间的移动、拖放） | `build` |
| 滚轮滚动某个由框架保留偏移的 Scroll 容器（分发阶段直接换算并夹紧偏移，不进入收件列表，REQ-INPUT-020） | `layout`；偏移未变（已到尽头）则不置脏。该容器内有布局反馈节点（虚拟化控件）时按 REQ-FRAME-031 升级为构建 |
| 焦点转移（产生 `focus_gained`/`focus_lost`，进入收件列表，REQ-INPUT-045） | `build` |
| 悬停目标变化、按下视觉态变化、焦点环显隐 | 仅对**外观依赖该状态**的节点置 `paint`：节点经 `ui.interact` 登记了相应兴趣且其控件的绘制读取 `Visual.hovered`/`pressed`/`focus_t` 等（由控件在 `InteractOpts.sense` 之外以 `NodeFlags.hover_visual` 声明，默认随 `sense.click`/`sense.drag` 为真）。仅为提示框、指针形状或 `hovered` 查询而登记悬停的节点，悬停变化不置脏、不产生帧。设置了"悬停影响构建"标志的节点置 `build` |
| 无捕获、悬停目标不变的鼠标移动 | 不置脏，不产生帧 |
| 应用调用 `window.invalidate(level)` / `ui.invalidate(level)`（模型通知） | 调用方指定，默认 `build` |
| 控件定时器到期 | 定时器登记时指定的级别 |
| 活动动画推进 | 动画登记时指定：`paint`（仅该节点）或 `build` |
| 窗口客户区尺寸变化 | `layout`；损伤为整根（帧缓冲内容视为丢失，REQ-GFX-007） |
| DPI 变化、主题/强调色/高对比度变化、字体设置变化 | `build`，并清空度量与排版缓存 |
| 系统要求重绘（遮挡后恢复、帧缓冲内容丢失） | `paint`，损伤为系统给出的区域或整窗 |
| 窗口激活状态变化 | `paint` 整窗（非活动窗口的选中色与焦点环不同）；并通知输入模块 |

**REQ-FRAME-038**　同一轮消息处理中的多次置脏**必须**合并：级别取最高，损伤取并。它们只导致一帧。

**REQ-FRAME-039**　布局阶段**必须**做增量复用：对新树中的每个节点，若在旧树中存在同 ID 节点、两者布局输入的哈希相等、且本次给它的可用空间约束与上次相同，则直接沿用旧节点的测量结果，不进入其子树测量。

**REQ-FRAME-040**　损伤由以下各项的并集构成，以物理像素整数矩形表示，向外取整：
1. 新旧树中同 ID 节点：若最终矩形不同，损伤 = 旧矩形 ∪ 新矩形；若矩形相同但绘制键不同，损伤 = 该矩形。
2. 仅存在于旧树的节点：其旧矩形。仅存在于新树的节点：其新矩形。
3. 交互视觉态变化或有 `paint` 级活动动画的节点：其矩形。
4. 显式的 `invalidateRect`。
5. 系统要求重绘的区域。

计入损伤前，每个节点的矩形先与其全部祖先的有效裁剪矩形求交（被滚动出视口的内容不产生损伤）。

节点的"矩形"在此指其**绘制范围**：布局矩形向外扩展该节点声明的绘制外延（焦点环、阴影等，由控件以令牌声明，默认 0）。

**REQ-FRAME-041**　每个根的损伤保存为至多 8 个互不包含的矩形。超过 8 个时合并面积增量最小的一对。损伤总面积超过该根面积的 50% 时，**必须**改为整根重绘。

**REQ-FRAME-042**　绘制阶段**必须**把裁剪区设为损伤矩形，并只对绘制范围与损伤相交的节点调用绘制函数；祖先节点的背景在相交时也要重绘，以保证损伤区内的像素被完整覆盖。

**REQ-FRAME-043**　任何一帧，不论执行了哪些阶段（含只有 `paint` 脏的帧），只要损伤计算的结果为空，该帧**不得**绘制、**不得**提交。

**REQ-FRAME-044**　帧缓冲内容不可保留的情况下（04 定义何时发生），当帧的损伤**必须**提升为整根。

### 3.8 动画与定时器

**REQ-FRAME-045**　`ui.animate(id, slot, target, spec)` 返回该 `(id, slot)` 动画值在本帧时间戳的当前值。首次调用时值直接等于 `target`（无入场动画）；此后 `target` 改变时，从当前值按 `spec` 的时长与缓动向新目标过渡。动画状态存于框架内建的每节点交互状态中。 循环动画用 `ui.animateLoop(id, slot, period, level)`：返回 `[0,1)` 的相位 = `(本帧时间戳 mod 周期) / 周期`，只要节点持续声明它就保持为活动动画（REQ-FRAME-048）；REQ-FRAME-047 的条件成立时恒返回 0 且不登记；REQ-FRAME-049 同样适用。

**REQ-FRAME-046**　`spec` **必须**引用主题的动效令牌（09），并指定影响级别：`paint`（默认）或 `build`。值只影响绘制的动画（颜色、透明度、高亮位置）**必须**用 `paint` 级，此时每个动画帧不执行构建与布局。

**REQ-FRAME-047**　当系统关闭了界面动画（Win32：`SPI_GETCLIENTAREAANIMATION` 为假），或应用设置了"禁用动效"，`animate` **必须**立即返回 `target`，不登记活动动画。

**REQ-FRAME-048**　只要某个根存在活动动画，该 `Ui` 就以该窗口所在显示器的垂直同步节奏连续出帧。全部动画到达目标的那一帧结束后，**必须**回到阻塞等待。

**REQ-FRAME-049**　窗口最小化或完全不可见时，动画**必须**暂停出帧；恢复可见时，所有动画直接跳到目标值并产生一次整根绘制。

**REQ-FRAME-050**　`ui.timer(id, interval_ms, level)` 登记一个属于节点的重复定时器，返回值表示"自上次查询以来是否到期过"。定时器随节点存活：某次构建未再登记即取消。到期时按 `level` 置脏。定时器精度为毫秒级，允许与其他唤醒合并，延迟不超过一个垂直同步周期。 `ui.timerRestart(id)` 使该节点的定时器从本帧时间戳重新计时（文本光标在每次编辑或移动后用它回到"亮"相位）。`paint` 级定时器的损伤是登记它的那个节点的绘制范围；需要窄损伤的闪烁元素**必须**声明为独立的叶节点（文本光标是文本框的一个子叶节点），而不是让整个控件重绘。

**REQ-FRAME-051**　文本光标闪烁**必须**用 `paint` 级定时器实现，周期读取系统设置（Win32：`GetCaretBlinkTime`；返回"不闪烁"时光标常亮且不登记定时器）。闪烁帧只重绘光标所在的损伤矩形。

### 3.9 调度

**REQ-FRAME-052**　界面线程的主循环**必须**是：处理完当前队列中的全部平台消息与回投 → 若任一 `Ui` 有脏标记则各运行一帧 → 若存在活动动画则等待下一个垂直同步或新消息（先到者）→ 否则计算最近的定时器到期时间并阻塞等待消息至多到该时刻；无定时器时无限期阻塞。

**REQ-FRAME-053**　在无脏标记、无活动动画的状态下，主循环**不得**产生任何帧，线程**必须**处于操作系统的阻塞等待中。

**REQ-FRAME-054**　输入到达至对应帧开始之间不得人为延迟：消息队列一旦取空，脏帧立即开始。为合并高频输入（鼠标移动、滚轮），一帧运行期间到达的事件留待下一轮统一处理。

**REQ-FRAME-055**　操作系统进入其内部模态循环（拖动窗口边框缩放/移动、系统菜单）期间，帧由平台层在相应的系统回调中驱动（03），本节的阶段规则不变。

**REQ-FRAME-056**　多个应用窗口各有独立的 `Ui`，在同一界面线程上轮流出帧；一个窗口的失效不导致其他窗口出帧。`app.invalidateAll(level)` 用于模型被多个窗口共享的情况。

### 3.10 调试设施

**REQ-FRAME-057**　框架**必须**提供下列调试设施。其中"帧统计"在所有构建模式下提供（计时类字段的启用条件见 REQ-ARCH-021），其余三项仅调试构建提供：
- `-Dforce-rebuild`：每帧置 `build` 脏并整根重绘，用于排查遗漏的模型通知与错误的绘制键。在此开关下界面表现与关闭时不同，即说明存在失效缺陷。
- `-Dshow-damage`：每帧在覆盖层以半透明色闪烁标出损伤矩形。
- 帧统计：每帧的构建遍数、节点数、复用度量的节点数、被绘制的节点数、损伤面积、各阶段耗时，通过 `core.stats` 暴露（名字见 12 的埋点清单）。恒有：被绘制的节点数 ≤ 节点数，复用度量的节点数 ≤ 节点数。
- 节点检视：按住约定热键时，悬停节点的 ID、调用点、矩形、状态槽列表显示在覆盖层。

## 5. 边界与错误情况

| 情况 | 规定 |
|---|---|
| 构建函数在两遍之间产出不同的树（违反幂等） | 无法普遍检测。`-Dforce-rebuild` 下界面抖动即为征兆。调试构建可选开启"幂等校验"：在无事件帧额外构建一遍并比对树哈希，不同则报告首个差异节点。 |
| 节点在第二构建遍消失，但第一遍已消费了它的事件 | 事件视为已消费，不重投。 |
| 拥有输入捕获或焦点的节点在构建后不再存在 | 捕获立即释放；焦点按 08 的规则转移。在布局前处理。 |
| 构建遍内创建又未触达的槽 | 不可能：创建即触达。 |
| `sticky` 槽的保留节点持有大量内存 | 保留节点**应当**实现可选的 `trim(*T)`，在连续 N 次构建未触达后由框架调用以释放缓存但保留核心状态。 |
| 首帧 | 无保留树：分发阶段无命中目标；`lastRect` 全为 `null`；损伤为整根；允许因布局反馈执行第二遍。 |
| 窗口尺寸为 0 或最小化 | 不构建、不布局、不绘制；脏标记保留到恢复。 |
| 一帧耗时超过垂直同步周期 | 不补帧。动画以时间戳求值，自然跳过中间值。 |
| 构建函数内调用 `ui.invalidate` | 允许，结果是下一帧（REQ-FRAME-023）；若无外部原因地每帧都调用，即构成失效风暴。 |
| 绘制函数内试图修改状态或置脏 | 调试构建断言中止（`PaintCtx` 只暴露常量访问）。 |
| 时间戳回绕 | 使用 64 位毫秒单调时钟，不考虑回绕。 |

## 6. 验收标准

除特别注明外，以下测试在降级后端上以无头方式运行，使用可注入的假时钟与假垂直同步。

**AC-FRAME-001**　`[单元]` 覆盖：REQ-FRAME-001、REQ-FRAME-002、REQ-FRAME-003、REQ-FRAME-007。构建：同一行调用两个不同键的叶节点；同一调用点位于两个不同容器内；`pushId` 嵌套两层。预期：所有 ID 互不相同且非 0；重复构建同一函数 100 次，每个节点的 ID 不变。另以构造的输入令哈希函数返回 0，预期 ID 为 1。

**AC-FRAME-002**　`[单元]` 覆盖：REQ-FRAME-004、REQ-FRAME-005。在循环中不带键地调用同一控件两次。预期：调试构建中止，消息含调用点的文件与行号；发布构建不崩溃，两节点共享状态，`err` 日志恰好 1 条（连续 10 帧后仍为 1 条）。

**AC-FRAME-003**　`[单元]` 覆盖：REQ-FRAME-004。以稳定键渲染 5 项列表，每项含一个有滚动状态的子控件；修改第 2 项的状态后交换第 2、4 项的顺序重建。预期：状态跟随数据项而非位置。

**AC-FRAME-004**　`[单元]` 覆盖：REQ-FRAME-006。检查公开 API 与设置持久化格式。预期：不存在把 `WidgetId` 序列化的入口；持久化键均为字符串名。

**AC-FRAME-005**　`[单元]` 覆盖：REQ-FRAME-008、REQ-FRAME-009、REQ-FRAME-010。测试一：节点 A 以 `transient` 持有计数槽，写入 7；下一次构建不声明 A；再下一次构建重新声明 A。预期：读到初值而非 7。测试二：同上但用 `sticky`。预期：读到 7。测试三：创建 5000 个 `sticky` 槽后全部不再触达（上限 4096）。预期：存活槽数 = 4096，被回收的是最早创建的 904 个。测试四：同一 ID 分别请求 `u32` 与 `f32` 槽，写入不同值，互不影响。

**AC-FRAME-006**　`[单元]` 覆盖：REQ-FRAME-011、REQ-FRAME-012。保留节点类型在 `init`/`deinit` 中递增计数器。场景：声明后停止声明（transient）；`forget`；`forgetSubtree` 作用于含 3 个保留节点后代的容器；关闭窗口。预期：每个场景下 `deinit` 次数等于被回收的保留节点数，且泄漏检测无报告。

**AC-FRAME-007**　`[单元]` 覆盖：REQ-FRAME-013、REQ-FRAME-045。对一个从未申请状态槽的节点调用 `animate`。预期：首次返回 `target`；改变 `target` 并推进假时钟至时长的 50%，返回值严格介于新旧目标之间；推进至 100% 返回新目标；节点停止声明一次构建后再出现，首次调用又直接返回 `target`。

**AC-FRAME-008**　`[单元]` 覆盖：REQ-FRAME-014、REQ-FRAME-015、REQ-FRAME-018。构建后连续触发 100 个纯绘制帧（`invalidateNode(.paint)`）。预期：构建函数调用计数不变；绘制函数被调用 100 次且每次看到的节点属性指针与内容相同；调试构建中，绘制函数内调用置脏 API 导致断言中止。

**AC-FRAME-009**　`[回放]` 覆盖：REQ-FRAME-016、REQ-FRAME-022。打开一个弹出层后，仅使宿主中一个按钮悬停变化。预期：宿主根绘制 1 次、提交 1 次；弹出根绘制 0 次、提交 0 次。再仅使弹出层内一项悬停变化，预期相反。

**AC-FRAME-010**　`[金图]` 覆盖：REQ-FRAME-017。内容层中后声明的兄弟与先声明的兄弟重叠；覆盖层绘制一条横贯的指示线。预期：后声明者盖住先声明者；指示线盖住两者；鼠标位于指示线上时命中的是内容层节点。

**AC-FRAME-011**　`[单元]` 覆盖：REQ-FRAME-019、REQ-FRAME-040、REQ-FRAME-043。场景一：以相同模型连续 `invalidate(.build)` 两次（两帧）。预期：第二帧构建计数 +1、绘制节点数 0、提交次数 +0。场景二：仅改变一个标签的文本（宽度不变的等宽替换）。预期：损伤恰为该标签的矩形。场景三：令一个节点右移 10 lpx。预期：损伤 = 旧矩形 ∪ 新矩形。场景四：移除一个节点 / 新增一个节点。预期：损伤分别包含其旧 / 新矩形。场景五：节点声明绘制外延 2 lpx 且悬停变化。预期：损伤为其布局矩形各边外扩 2 lpx（按缩放换算并向外取整）。

**AC-FRAME-012**　`[单元]` 覆盖：REQ-FRAME-020、REQ-FRAME-021。用带阶段日志的测试桩跑一帧"点击按钮使标签变化"。预期：阶段日志顺序恰为 收集→分发→构建→布局→损伤→绘制→提交→收尾；帧内所有 `ui.now()` 与 `PaintCtx.now` 返回同一值，即使假时钟在阶段之间被推进。

**AC-FRAME-013**　`[单元]` 覆盖：REQ-FRAME-023。在构建函数内调用 `ui.invalidate(.build)` 一次（仅首帧）。预期：构建函数不被嵌套调用（调用深度计数最大为 1）；随后恰好多出一帧。

**AC-FRAME-014**　`[单元]` 覆盖：REQ-FRAME-024、REQ-FRAME-025。对"控件总览"页开启幂等校验，运行全部回放脚本。预期：零差异报告。另备一个故意在构建中自增计数并显示的反例。预期：校验报告指出该标签节点。

**AC-FRAME-015**　`[单元]` 覆盖：REQ-FRAME-026、REQ-FRAME-027。在按钮的 `clicked` 分支内用 `afterFrame` 登记一个闭包，闭包内记录"提交计数"。预期：闭包执行时提交计数已包含本帧；闭包执行时帧状态已清除（帧竞技场已重置）；闭包执行期间触发的失效产生独立的新帧，帧调用深度计数始终 ≤ 1。调试构建下，在构建函数内直接调用 `platform.messageBox`，预期断言中止。构建函数耗时由 AC-PERF 系列约束。
