## 2. 规范性用语

| 用语 | 含义 |
|---|---|
| **必须** / **不得** | 强制要求。不满足即不合规，无例外。 |
| **应当** / **不应** | 默认要求。偏离需在实现处写明理由并经评审。 |
| **可以** | 允许但不要求。 |

没有使用上述用语的句子是说明性文字，不构成要求。

## 3. 条款编号

- 规范条款：`REQ-<域>-<三位序号>`，例如 `REQ-FRAME-012`。控件域形如 `REQ-W-BUTTON-003`。
- 验收条款：`AC-<域>-<三位序号>`，每条必须写明"覆盖：REQ-…"。
- 编号在域内从 001 起顺延，发布后不复用、不重排。废弃条款保留编号并标"（已废弃，见 …）"。
- 每条 `REQ` 至少被一条 `AC` 覆盖；每条 `AC` 必须出现在 [acceptance/](acceptance/) 的且仅一个里程碑清单中。
- 条款的定义处格式固定为行首加粗：`**REQ-FRAME-012**　正文`。引用处直接写编号，不加粗。检查脚本依赖此格式。

## 4. 验收条款的写法

一条合格的 AC 必须同时具备：

1. **前置条件**：环境、窗口状态、输入数据。
2. **操作步骤**：可由人或输入回放脚本逐步执行。
3. **可判定的预期结果**：数值、像素比对、状态断言、日志计数之一。禁止"流畅""自然""体验良好"等不可判定表述。
4. **验证方式标签**，取其一：
   - `[单元]` 纯逻辑测试，无窗口。
   - `[金图]` 无头渲染后与基准图像比对（见 13）。
   - `[回放]` 注入输入事件序列后断言状态或金图。
   - `[计量]` 读取埋点计数器或计时器（见 12）。
   - `[人工]` 必须由人执行并判定：在真实 Windows 上操作确认，或对代码/界面/流程做评审。只在无法自动化时使用，并写明观察要点或评审清单。

## 5. 各类文档的固定章节

**规范文档（01–09、11–13、15）**：1 范围 → 2 术语（仅本文新增的）→ 3 规范条款（可分小节）→ 4 接口草案 → 5 边界与错误情况 → 6 验收标准 → 7 待定问题。某章确无内容时写"无"，不得删章。

**控件文档**：见 [10-widgets/_template.md](10-widgets/_template.md)。

**ADR**：状态 / 背景 / 决策 / 后果 / 被否方案。状态取"已采纳""已取代（→ 编号）"。

## 6. 接口草案的写法

- 用 Zig 语法写**签名与类型定义**，不写函数体。目的是固定名字、参数、所有权与错误集，不是提供实现。
- 草案代码块统一标 ```` ```zig ````，首行注释 `// 草案：仅签名`。
- 草案中的名字一经在两份以上文档中被引用即视为冻结，改名需同步所有引用处。

## 7. 单位与坐标

| 名称 | 标识 | 定义 |
|---|---|---|
| 逻辑像素 | `lpx` | 与 DPI 无关的长度单位。96 DPI 下 1 lpx = 1 物理像素。所有规范、令牌、API 默认使用 lpx。 |
| 物理像素 | `ppx` | 帧缓冲的实际像素。`ppx = lpx × scale`。 |
| 缩放系数 | `scale` | `窗口 DPI / 96`，例如 1.0、1.25、1.5、2.0。每窗口独立。 |
| 坐标系 | — | 原点在窗口客户区左上角，x 向右，y 向下。 |
| 时间 | `ms` | 毫秒。单调时钟。 |
| 颜色 | — | sRGB，非预乘，写作 `#RRGGBB` 或 `#RRGGBBAA`。 |

## 8. 术语表

全文档集统一使用下列术语。括号内是代码中使用的英文标识。

| 术语 | 定义 |
|---|---|
| 受控即时模式 | 界面每帧由构建函数重新声明（即时风格），但帧只在失效时才执行，且跨帧状态由框架按 ID 保留。 |
| 帧 (frame) | 一次完整的"事件分发 → 构建 → 布局 → 绘制 → 提交"。 |
| 构建函数 (build fn) | 应用提供的、调用控件 API 声明界面的函数。 |
| 构建 (build) | 执行构建函数，产出本帧的节点树。 |
| 节点 (node) | 构建阶段产生的一个界面元素记录，含 ID、布局参数、绘制函数与属性。有效期为本次构建到下一次构建。 |
| 控件 ID (WidgetId) | 64 位哈希，跨帧标识同一个逻辑控件。 |
| 状态槽 (state slot) | 状态存储中以控件 ID 为键、跨帧存活的一块数据。 |
| 保留节点 (retained node) | 重型控件拥有的、跨帧存活且自管理内部缓存的对象。是状态槽的特例。 |
| 失效 (invalidate) | 声明界面的某部分已过期，请求一次未来的帧。 |
| 失效源 | 允许触发失效的来源：输入、定时器、动画、模型通知、系统事件。 |
| 构建脏 (build-dirty) | 界面结构或数据可能变化，需要重跑构建函数。三级脏标记中最高一级。 |
| 布局脏 (layout-dirty) | 节点的尺寸或位置可能变化，需要重新测量与排布。 |
| 绘制脏 (paint-dirty) | 节点外观变化但几何不变，只需重绘。 |
| 损伤矩形 (damage rect) | 本帧需要重绘的屏幕区域，物理像素、整数。 |
| 被动刷新 | 没有失效时线程阻塞在消息等待，不产生帧。 |
| 帧竞技场 (frame arena) | 每帧开始时整体重置的线性分配器。 |
| 树竞技场 (tree arena) | 存放节点树的线性分配器，共两份，每次构建互换。 |
| 根 (root) | 一棵节点树的顶点，对应一个平台窗口表面。一个界面上下文可有多个根（主根与各弹出层根）。 |
| 激活类结果 | 控件向应用报告的一次性交互结果：点击、值改变、提交等。 |
| 令牌 (token) | 主题中具名的颜色、尺寸、时长等值。 |
| 表面 (surface) | 主题中的背景层级：窗口底、面板、凸起、内凹、浮层。注意与渲染资源 `gfx.Surface`（一个根的帧缓冲，见 04）区分；后者在行文中始终写作代码名。 |
| 弹出层 (popup) | 菜单、下拉、提示等由独立无边框顶层窗口承载的界面。 |
| 宿主窗口 (owner) | 弹出层所从属的窗口。 |
| 平台层 (platform) | 封装窗口、消息、输入法、剪贴板等操作系统能力的模块。 |
| 一等后端 | Win32 后端。规范中的全部条款对其生效。 |
| 降级后端 | GLFW 后端。仅保证 03 降级矩阵中列出的能力。 |
| 模型 (model) | 应用自己的数据。框架不拥有，只接收其变更通知。 |
| 命令 (command) | 具名的、可绑定到菜单/工具栏/快捷键的应用动作。 |
