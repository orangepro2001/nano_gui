# ADR 0006：被动刷新与三级脏标记

**状态**：已采纳

## 背景
桌面应用绝大部分时间处于静止。空闲时不应消耗 CPU/GPU，交互时应只重算与重绘必要的部分。

## 决策
- **被动刷新**：没有待处理的失效时，界面线程阻塞在操作系统的消息等待上（Win32：`MsgWaitForMultipleObjectsEx`/`GetMessage`；GLFW：`glfwWaitEvents`）。不存在空转的主循环。
- **失效源是封闭集合**：输入事件、定时器到期、动画推进、模型通知（应用显式调用）、系统事件（尺寸、DPI、主题、焦点、显示设置变化）。除此之外不得触发帧。
- **三级脏标记**，逐级包含：
  1. **构建脏**：界面结构或数据可能变化，需要重跑构建函数。模型通知与大多数输入事件置此标记。
  2. **布局脏**：某些节点的尺寸/位置需要重算。构建后与上一帧对比布局输入得出；未变化的子树复用上一帧的度量结果。
  3. **绘制脏**：只有外观变化（如悬停高亮、光标闪烁、动画中间帧）。产生损伤矩形，仅重绘该区域。
- 节点树在两次构建之间保留。纯绘制脏的帧（例如光标闪烁、悬停高亮）跳过构建与布局，只对保留树中与损伤矩形相交的节点重新执行绘制；纯布局脏的帧（例如窗口缩放）跳过构建，对保留树重新布局。
- 同一轮消息处理内的多次失效合并为一帧。
- 动画期间以垂直同步节奏出帧；所有动画结束后回到阻塞等待。

## 后果
- 空闲 CPU 占用为零，笔记本上不唤醒独显。
- 需要在两次构建之间保留节点树及其几何（即"不完全放弃保留模式"的一部分），内存占用略增。
- 局部重绘要求帧缓冲内容在帧间保留，需要相应的交换链/帧缓冲策略（见 04）。
- 应用若忘记发出模型通知，界面不会更新。这是有意的显式契约；调试构建提供"强制每帧重建"开关用于排查。

## 被否方案
- **固定 60fps 主循环**：实现最简单，持续耗电。
- **只有一个全局脏位**：任何变化都全量重建重绘；光标闪烁这类高频小变化代价过高。
- **自动依赖跟踪**（信号/观察者自动订阅）：隐式、难以掌控，与设计目标不符。
