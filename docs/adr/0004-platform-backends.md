# ADR 0004：Win32 为一等后端，GLFW 为降级后端

**状态**：已采纳

## 背景
目标平台是 Windows，但日常开发与自动化测试在 Linux 上进行。需要明确两个平台后端的地位，避免为了"跨平台一致"而削弱原生契合度。

## 决策
- 定义统一的平台抽象接口 `platform`（见 03），上层只依赖该接口。
- **Win32 后端是一等后端**：直接使用 Win32 API（不经 GLFW），全部规范条款对其生效，包括 Per-Monitor DPI v2、DWM、输入法、OLE 拖放、通用对话框、托盘、多窗口弹出层、UI Automation。
- **GLFW 后端是降级后端**：只在 Linux 上使用，用途是开发期快速迭代、无头渲染测试、输入回放测试。能力以 03 的降级矩阵为准；矩阵中标为"不支持"的能力，接口返回 `error.Unsupported` 或文档规定的退化行为，上层不得因此分叉业务逻辑。
- 接口以 Win32 的能力为基准来设计，GLFW 后端去适配它，而不是取两者交集。
- macOS 不在范围内，接口设计不为其预留。

## 后果
- Windows 上可以做到与原生应用同等的系统集成，不受 GLFW 抽象限制（例如缩放期间同步重绘、自定义命中测试、输入法候选窗定位）。
- 需要维护两套平台代码，但降级后端体量小且要求低。
- 存在"Linux 上通过、Windows 上才暴露"的问题类别；因此凡标 `[人工]` 的验收以及全部 PLAT 域验收必须在真实 Windows 上执行。

## 被否方案
- **仅 Win32**：最简单，但 Linux 开发机无法运行任何界面，迭代效率过低。
- **仅 GLFW（含 Windows）**：一套代码，但 GLFW 屏蔽了大量原生细节，与"深度契合原生 API"直接冲突。
- **两者对等**：把 Linux 当正式目标会成倍增加规范与测试面，当前无此需求。
