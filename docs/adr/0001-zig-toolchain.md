# ADR 0001：以 Zig 为唯一实现语言，固定工具链版本

**状态**：已采纳

## 背景
框架要求不依赖任何上层语言运行时（无 GC、无虚拟机、无脚本引擎），并能直接调用 Win32 与 C 库。需要选定语言与版本策略。

## 决策
- 框架与应用代码全部用 Zig 编写。C 仅以第三方库源码形式存在（NanoVG、GLFW、stb），由 `build.zig` 直接编译，不引入 CMake/Make。
- 工具链固定为 **Zig 0.17.1**，版本号写入 `build.zig.zon` 的最低版本字段与 CI。升级 Zig 版本是一次独立的、单独提交的工作，不与功能改动混合。
- Win32 API 绑定由本项目自行声明所需子集（按需增补），不依赖运行时反射或大型自动生成绑定包。
- 产物是单个静态链接的可执行文件；除系统自带 DLL（user32、gdi32、dwmapi、dwrite、opengl32、ole32、imm32 等）外无运行时依赖。

## 后果
- 可以从 Linux 交叉编译 Windows 目标，开发机不需要 Windows 即可产出可执行文件。
- Zig 尚未 1.0，语言与标准库会有破坏性变更；固定版本把这一风险集中到"升级"这个可计划的动作上。
- 自写 Win32 绑定有前期成本，但换来对 ABI 与调用约定的完全掌控，且只包含用到的部分。

## 被否方案
- **C/C++**：缺少内建的交叉编译与构建系统，错误处理与内存安全全靠约定。
- **Rust**：编译时间与抽象层级不符合"高度可掌控"的目标，C 互操作不如 Zig 直接。
- **跟随 Zig 最新版**：每次升级都可能打断开发，且无法复现历史构建。
