# ADR 0007：一维盒布局，不做 CSS Grid

**状态**：已采纳

## 背景
布局系统的复杂度直接决定每帧成本与可预测性。CSS Grid 与完整 Flexbox 含有多轮求解、隐式轨道、内容回流等机制，实现与调试成本高，桌面工具类界面极少需要。

## 决策
- 布局基元只有：**Row**（横排）、**Column**（竖排）、**Stack**（子项叠放在同一矩形内，各自对齐）。
- 子项在主轴上的尺寸策略三选一：**固定**（lpx）、**适应内容**（fit）、**伸展**（grow，带权重）；均可叠加 min/max 约束。交叉轴上：固定、适应内容、填满。
- 容器属性：padding、gap、主轴对齐（仅在无伸展子项时有意义）、交叉轴对齐。
- 专用容器覆盖常见二维需求：**Table**（列宽由表头定义，行内单元格共享列宽）、**Form**（两列"标签-字段"，标签列取最宽标签）、**Splitter**、**Scroll**、**Anchor**（相对某矩形定位，用于弹出层与徽标）。
- 求解固定为**两遍**：自底向上测量（给定可用空间上限，返回期望尺寸），自顶向下排布（给定最终矩形）。不允许子项尺寸依赖兄弟的排布结果；不做多轮迭代。唯一的例外是自动换行文本的"宽度定后求高度"，在测量遍内以一次回调完成。
- 不做：自动换行的流式容器（wrap）、基于内容的列自动均衡、百分比单位、margin 折叠、z-index、绝对定位的任意嵌套。
- 排布结果一律对齐到整数物理像素。

## 后果
- 布局成本为 O(节点数)，行为可手算预测。
- 少数需要真二维对齐的界面（如属性面板）用 Form/Table 解决；超出范围的布局由应用自写一个自定义容器（接口见 07），而不是扩张通用系统。
- 缺少流式换行；工具栏溢出用"溢出菜单"而非换行处理。

## 被否方案
- **完整 Flexbox**：shrink、wrap、baseline 对齐带来的多轮求解不值得。
- **CSS Grid**：用户明确排除。
- **约束求解（Cassowary）**：表达力强但成本与可预测性差。
