# 14 路线图

本文把实现工作切分为七个里程碑。每个里程碑有明确的范围、交付物与退出条件；**退出条件一律是 [acceptance/](acceptance/) 中对应清单的全部条款通过**，此外不设主观标准。里程碑严格顺序推进：前一个未退出，不开始后一个的实现（可以提前阅读与细化后续规范）。

本阶段（规划）只产出文档。M0 是第一个写代码的里程碑。

## M0　工具链与空窗口

**目标**：仓库骨架立起来；Windows 上出现一个行为正确的空窗口，Linux 上出现降级后端的空窗口；从 Linux 能交叉编译出 Windows 可执行文件。

**范围**
- `build.zig` 与 REQ-ARCH-022 规定的全部步骤名（尚无内容的步骤可为空操作但必须存在）。
- 目录结构与模块边界（02），导入检查脚本，`zig build check-docs`。
- `core`：数学类型、哈希、帧竞技场、日志、统计计数器。
- `platform` Win32：窗口类与创建、主循环（阻塞等待）、Per-Monitor DPI v2、DWM 深色标题栏、尺寸变化、关闭请求、WGL 上下文与清屏呈现、`fatal`、系统外观与系统度量的读取与变化通知。
- `platform` GLFW：窗口、循环、无头模式、假时钟与事件注入的骨架。
- NanoVG 与 GLFW 源码 vendoring（需先决定 OPEN-001）。

**不含**：任何绘制内容（只清屏为 `surface_window` 色）、文字、输入路由。

**主要风险**：WGL 上下文在远程桌面/虚拟机环境下的可用性；缩放窗口时的同步呈现。两者都要在本里程碑内实机摸清，结论回写 03 与 ADR 0002。

## M1　渲染与文字

**目标**：`gfx.Canvas` 与 `text` 可用；能在窗口里画出像素精确的图形和系统质量的文字；金图测试跑通。

**范围**
- `gfx`：Canvas 全部接口、持久离屏帧缓冲与局部重绘的呈现路径、裁剪、图像解码与纹理缓存、`readPixels`。
- `text`：三个后端（DirectWrite、fontstash、固定度量测试后端）、排版与度量、排版缓存、字形图集、省略、命中测试与光标/选区几何。
- 金图测试基础设施（13）与首批基准。

**不含**：输入法组字绘制（M4）、彩色 emoji（M6）。

**主要风险**：DirectWrite 灰度光栅在 100% 缩放下的小字清晰度；分数缩放下发丝线与文字基线的像素对齐。本里程碑末做一次实机观感评审，必要时修订 ADR 0003。

## M2　帧模型、布局、输入

**目标**：受控即时模式跑通。能用构建函数声明由"带色矩形 + 文字"构成的可交互界面；被动刷新、三级脏标记、局部重绘全部按规范工作。

**范围**
- `ui`：ID、状态存储、节点树与双份树竞技场、帧的八个阶段、第二构建遍、损伤计算、动画、定时器、调度、调试设施（06 全部）。
- `layout`：Row/Column/Stack、尺寸策略与求解、增量复用、布局反馈、Scroll 的布局语义、自定义容器接口。
- `input`：命中测试、悬停、捕获、点击/双击/拖拽判定、滚轮路由、焦点与 Tab 序、焦点可见、键盘路由优先级（弹出层与输入法两级留空）、指针形状。
- 输入回放测试基础设施与脚本格式（13）。

**不含**：主题绘制（用调试色块代替）、弹出层、输入法。

**主要风险**：同帧第二构建遍与事件只投递一次的交互细节；增量布局复用的正确性。以 AC-FRAME-024 的随机交互比对作为主要防线。

## M3　主题与基础控件

**目标**：Instrument 主题落地；一批无弹出层、无文本编辑的控件达到规范；"控件总览"示例页成形。

**范围**
- `theme`：令牌表、强调色派生、校验、全部绘制基元、高对比度、系统设置响应（09 全部）。
- 控件：label、button、checkbox、radio、switch、slider、progress、separator、group-box、image/icon、scrollbar/scroll-view、splitter、tabs、toolbar、status-bar。
- 布局专用容器 Splitter、Form 的布局语义。
- "控件总览"示例页（即 12 的参考界面 G 的雏形）与"自定义控件"示例（AC-ARCH-003）。

### 参考界面 G（"控件总览"页）的组成

12 的性能预算、01 与 09 的若干验收都以这一页为对象。其组成在此冻结；改动它等同于改动预算的测量对象，须与 12 的基线一并更新。

页面是一个应用窗口（1280×800 lpx 客户区），结构为：菜单栏 → 工具栏 → 标签页（6 页）→ 状态栏。**参考界面 G 指"全部"页处于当前页时的整窗**，该页把其余五页的内容纵向排在一个滚动容器里，用于整体计量；其余五页用于分项金图与回放。

| 区域 | 内容 | 约计节点数 |
|---|---|---|
| 菜单栏 | 5 个顶层菜单（每个 6–10 项，含子菜单、勾选项、快捷键），全部绑定命令 | 10（菜单未展开） |
| 工具栏 | 12 个命令按钮、3 个分隔符、1 个下拉框、1 个搜索文本框、溢出按钮 | 45 |
| 标签条 | 6 个标签 + 溢出按钮 | 12 |
| "基础"区 | 状态矩阵：button（3 变体 × 3 尺寸 × 启用/禁用，另含带图标与仅图标）、checkbox（3 态 × 启用/禁用）、radio（两组各 4 项）、switch、链接与各文字样式的 label、separator、image（标记与位图各 4 个）；每组置于带标题的 group-box 内 | 260 |
| "输入"区 | 一个 Form：text-input（常态/占位/只读/禁用/密码/校验失败/带清除按钮各一）、spin-box（整数与小数）、combo-box（下拉列表与可编辑）、slider（水平 4 个、垂直 2 个，含刻度）、progress（确定 3 个、不确定 1 个）、一个 8 行高的 text-area（载入 200 行文本） | 230 |
| "列表"区 | 水平 splitter：左为 list（1 万行，多选，交替行色），右为 tree（3 层，展开后约 500 个可见节点）；各自视口约 20 行 | 190 |
| "表格"区 | table：10 万行 × 12 列，带排序标记，视口约 18 行 × 8 个可见列 | 330 |
| "布局"区 | 嵌套的 Row/Column/Stack 演示（3 层嵌套，含 grow 权重、`fit_shrink` 文本、对齐与间距各档）、垂直 splitter、嵌套 scroll-view | 280 |
| "文字"区 | 60 个 label：中英混排、长文本省略、自动换行段落、各字号字重、等宽数字列 | 90 |
| 状态栏 | 4 个窗格，其中一个含进度条 | 12 |
| 合计 | | 约 1460（12 的 REQ-PERF-003 允许区间 1400–1600） |

约束：页面的构建函数不含任何颜色或尺寸字面量（AC-VIS-005）；全部控件带 `debug_name`，供回放脚本定位；模型数据由固定种子生成，使金图与基准可复现。

**主要风险**：浅色主题边框偏重（OPEN-THEME-01）。本里程碑末做实机审美评审，对照 REQ-THEME-006 禁止项表逐条检查。

## M4　文本编辑、输入法、弹出层

**目标**：能输入中文；菜单、下拉、提示、对话框可用且行为与原生一致。

**范围**
- `platform`：IMM32 输入法、剪贴板、弹出窗口（创建、不激活、点击外部检测、阴影、多显示器定位）。
- `input`：弹出栈、轻关闭、键盘路由的弹出层与输入法两级、助记符、默认/取消按钮、上下文菜单触发。
- `text`：组字绘制支持。
- 布局 Anchor。
- 控件：text-input、text-area、spin-box、combo-box、menu-bar/menu/context-menu、tooltip、dialog/modal。

**主要风险**：这是行为条款最密集的里程碑。弹出窗口的激活/捕获/焦点在 Win32 上细节极多；输入法候选窗定位在多显示器与不同缩放下的正确性。预留充足的实机 `[人工]` 验收时间。

## M5　重型控件与应用模型

**目标**：能写出真实的工具型应用：大数据量的列表/树/表格，命令、菜单、快捷键、设置持久化、多窗口、原生对话框与拖放。

**范围**
- 控件（保留节点）：list（虚拟化）、tree、table。布局 Table 的语义。
- `app`：命令系统与快捷键、设置持久化、多窗口、应用内模态对话框、内建字符串表（11 全部）。
- `platform`：通用对话框、OLE 拖放、托盘、窗口位置持久化。
- `input`：应用内拖放。

**主要风险**：虚拟化控件的构建成本与布局反馈的收敛；表格在百万行下的选区与滚动模型。

## M6　无障碍、性能达标、示例应用

**目标**：全部预算达标；UI Automation 可用；三个示例应用证明框架可用于实际开发；全部验收清单关闭。

**范围**
- UI Automation 提供者与各控件的角色/模式（03 与各控件规范第 11 节）。
- 12 的全部基准场景与预算；`zig build bench` 的对照表与基线。
- 彩色 emoji 字形。
- 三个示例应用：① 文本编辑器（单文档，菜单/工具栏/状态栏/查找）；② 数据浏览器（树 + 表格 + 属性面板，百万行）；③ 设置面板（各类表单控件、对话框）。它们同时是 AC-THEME-003 的评审对象。
- 01 的全局验收（AC-VIS 系列）。
- 处理各文档"待定问题"中标注到 M6 的条目。

**主要风险**：UIA 的 COM 提供者体量；性能预算中绘制项在集成显卡上的达标情况（若不达标，启用 OPEN-FRAME-01 的子树绘制缓存）。

## 跨里程碑规则

1. **规范先行**：实现中发现规范有误或有缺口，先改文档（独立提交），再改代码。
2. **验收不后移**：属于某里程碑清单的 AC 不得挪到后面的里程碑，除非在清单末尾登记原因并得到确认。
3. **每个里程碑结束时**：在参考机上记录性能基线（12）；执行范围评审（AC-VIS-008）；回顾并更新各文档的待定问题表。
4. **示例即测试**：每个里程碑的示例程序都要有对应的回放脚本，纳入 `zig build test-replay`。
