# 01 愿景与范围

## 1. 范围

本文定义 nano_gui 要成为什么、不成为什么，以及贯穿全部设计的原则。其他文档在取舍时以本文原则的先后次序为准。

## 2. 术语

无新增。

## 3. 规范条款

### 3.1 定位

nano_gui 是一套供作者长期自用、反复积累的桌面应用开发套件：一个可执行文件、零运行时依赖、每一层都能读懂并修改。它面向**鼠标与键盘驱动的工具型应用**（编辑器、管理工具、调试器、配置面板、数据查看器），而不是内容展示型或触控优先的应用。

### 3.2 目标

**REQ-VIS-001**　框架及基于它的应用**必须**只用 Zig 编写，第三方代码仅限以源码形式编入的 C 库；最终产物**必须**是单个可执行文件，除操作系统自带组件外无运行时依赖。

**REQ-VIS-002**　一等目标平台**必须**是 Windows 10 版本 1809（内部版本 17763）及以上的 x64。Linux **必须**能运行降级后端以支撑开发与自动化测试。macOS **不得**作为设计考量。

**REQ-VIS-003**　界面**必须**采用受控即时模式（ADR 0005）与被动刷新（ADR 0006）：空闲时不产生帧，不占用 CPU。

**REQ-VIS-004**　凡操作系统对某种交互已有约定行为的（键盘导航、焦点、文本编辑按键、菜单、滚动、拖放、输入法、DPI、深浅色、高对比度、动画开关），框架**必须**遵循该约定，并从系统读取相应参数而非写死。

**REQ-VIS-005**　框架**必须**提供一套完整的默认主题 Instrument（ADR 0009），使未做任何视觉定制的应用即具备一致、精致的外观。

**REQ-VIS-006**　性能预算（见 12）是硬性验收项。任何功能若使预算被突破，**必须**先解决性能问题或缩减功能，不得以"以后优化"放行。

**REQ-VIS-007**　框架的每个公开行为**必须**有对应的规范条款与验收条款；没有写进文档的行为视为未定义，实现不得依赖。

### 3.3 非目标

**REQ-VIS-008**　以下内容**不得**进入框架，除非先以新 ADR 修改本条：

| 非目标 | 理由 |
|---|---|
| macOS、移动端、Web 目标 | 范围控制 |
| CSS Grid、完整 Flexbox、流式换行布局 | ADR 0007 |
| 样式表语言、选择器、级联、运行时换肤引擎 | 主题只是一张令牌表 |
| 标记语言或可视化设计器驱动的界面描述 | 界面即 Zig 代码 |
| 内嵌脚本语言或插件运行时 | "不依赖上层语言" |
| 自动依赖跟踪的响应式状态系统 | 显式失效，见 ADR 0006 |
| 自绘窗口标题栏 | ADR 0008 |
| 触控优先的手势与放大的触摸目标 | 定位为鼠标键盘应用；触摸与笔仅保证作为指针可用 |
| 富文本编辑、网页渲染、视频播放 | 超出工具型应用的共性需求 |
| 通用 3D 场景渲染 | 应用可自行在一块区域内使用 GL，但框架不提供场景抽象 |
| 从右到左（RTL）界面镜像 | 当前无需求；文字层仍须正确显示 RTL 文本片段 |

### 3.4 设计原则（按优先级降序）

取舍冲突时，靠前的原则优先。

**REQ-VIS-009**　**正确的原生行为优先于实现简便。** 用户不应察觉这不是原生应用——除了它更好看、更快。

**REQ-VIS-010**　**性能优先于功能广度。** 宁可少一个控件，不可多一毫秒的常驻成本。

**REQ-VIS-011**　**显式优先于隐式。** 失效要显式发出，ID 冲突要报错，所有权要写在签名里，没有隐藏的全局状态与后台线程。

**REQ-VIS-012**　**窄接口优先于灵活性。** 每个模块只暴露被两处以上真实用到的能力；特殊需求由应用自写，而不是给通用层加开关。

**REQ-VIS-013**　**克制优先于表现。** 视觉与动效上"不做"是默认选项；每一处装饰都要能回答"它帮用户理解了什么"。

**REQ-VIS-014**　**可读完优先于可复用。** 整个框架（不含第三方）的代码量**应当**保持在一个人能在数日内通读的规模；目标上限为 3 万行 Zig。

## 4. 接口草案

无。

## 5. 边界与错误情况

- 当某项原生行为在不同 Windows 版本间不一致时，以 Windows 11 当前稳定版的行为为准，并在相应条款中注明差异。
- 当降级后端无法实现某项原生行为时，按 03 的降级矩阵处理，不视为违反 REQ-VIS-004。

## 6. 验收标准

**AC-VIS-001**　`[计量]` 覆盖：REQ-VIS-001。对发布构建的可执行文件执行导入表检查（`dumpbin /dependents` 或等价工具）。预期：仅列出 Windows 自带 DLL；仓库中除 `third_party/` 外不存在非 Zig 源文件。

**AC-VIS-002**　`[人工]` 覆盖：REQ-VIS-002。在一台全新安装的 Windows 10 1809 x64 与一台 Windows 11 当前稳定版上，仅复制示例应用的单个 exe 并运行。预期：两者均正常启动并显示界面，无缺失组件提示。

**AC-VIS-003**　`[计量]` 覆盖：REQ-VIS-003。示例应用启动后静置 60 秒，无输入、无动画。预期：帧计数器在此期间增量为 0；进程 CPU 时间增量 < 10 ms。

**AC-VIS-004**　`[人工]` 覆盖：REQ-VIS-004、REQ-VIS-009。在系统设置中分别更改：双击速度、滚轮一次滚动行数、菜单显示延迟、关闭"在 Windows 中显示动画"、切换深/浅色、切换强调色、开启高对比度。预期：示例应用无需重启即随之变化，且各项行为与同机的记事本/资源管理器一致。

**AC-VIS-005**　`[金图]` 覆盖：REQ-VIS-005。运行"控件总览"示例页（包含全部控件的全部状态），应用代码中不出现任何颜色或尺寸字面量。预期：浅色、深色两套输出与基准图一致。

**AC-VIS-006**　`[计量]` 覆盖：REQ-VIS-006。执行 12 中的全部基准场景。预期：参考机 W 上全部硬性预算项达标，任一项超标即判失败；CI 机 L 上按 REQ-PERF-039 的硬性/趋势归属判定。

**AC-VIS-007**　`[单元]` 覆盖：REQ-VIS-007。运行文档检查脚本。预期：每条 REQ 至少被一条 AC 引用；每条 AC 出现在且仅出现在一个里程碑清单中；无重复编号。

**AC-VIS-008**　`[人工]` 覆盖：REQ-VIS-008、REQ-VIS-010、REQ-VIS-011、REQ-VIS-012、REQ-VIS-013。每个里程碑结束时进行范围评审，对照非目标表与原则清单检查本里程碑新增的公开 API。预期：无命中非目标的 API；每个新增的公开配置项都能指出至少两处真实使用。评审结论记录在里程碑清单末尾。

**AC-VIS-009**　`[计量]` 覆盖：REQ-VIS-014。统计 `src/` 下 Zig 代码行数（不含空行与注释）。预期：≤ 30 000；超过时须在路线图中登记精简计划。
